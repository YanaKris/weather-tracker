# weather-tracker

Мини-ETL на Python: собирает текущую погоду по нескольким городам из открытого API
[Open-Meteo](https://open-meteo.com/), накапливает историю в SQLite и формирует отчёт об
изменениях по сравнению с прошлым запуском.

Небольшой учебно-портфельный проект. Демонстрирует типовую автоматизацию процесса
**Extract → Transform → Load** с отчётностью, покрытием тестами (pytest) и статическим
анализом (ruff).

## Что делает

Одна команда `python -m src.main`:

1. запрашивает текущую погоду по списку городов (Open-Meteo, без API-ключа);
2. сохраняет замеры в локальную базу `data/weather.db` (SQLite, с дедупликацией повторов);
3. по каждому городу сравнивает свежий замер с предыдущим — изменение температуры;
4. считает сводную статистику по всей истории наблюдений — агрегатным SQL-запросом (`GROUP BY`);
5. печатает отчёт в консоль и сохраняет его в `report.md`.

Пайплайн устойчив к сбоям сети: если один город недоступен, он пропускается, а остальные
обрабатываются как обычно.

## Пример отчёта

```
# Отчёт о погоде — 2026-08-11 15:30

## Текущие замеры

| Город | Температура | Изменение | Ветер |
| --- | --- | --- | --- |
| Москва | 23.8 °C | +1.5 ↑ | 3.5 м/с |
| Санкт-Петербург | 17.2 °C | -0.4 ↓ | 3.5 м/с |
| Новосибирск | 24.8 °C | — | 2.6 м/с |

## Сводка за всё время наблюдений

| Город | Замеров | Средняя | Минимум | Максимум |
| --- | --- | --- | --- | --- |
| Новосибирск | 14 | 23.1 °C | 18.4 °C | 27.9 °C |
| Москва | 14 | 16.8 °C | 12.0 °C | 21.3 °C |
| Санкт-Петербург | 14 | 14.9 °C | 11.2 °C | 18.0 °C |
```

При первом запуске в колонке «Изменение» стоит «—» (сравнивать не с чем); при повторных
запусках появляются реальные изменения. Сводка наполняется смыслом за несколько запусков.

## Стек

Python 3 · `requests` · `sqlite3` (встроенный) · `pytest` · `ruff`

## Установка

```bash
python -m venv .venv
# Windows PowerShell:
.venv\Scripts\Activate.ps1
# Linux / macOS:
source .venv/bin/activate

pip install -r requirements.txt
```

## Запуск

```bash
python -m src.main
```

## Разработка

Зависимости для разработки (тесты и линтер):

```bash
pip install -r requirements-dev.txt
```

Тесты:

```bash
pytest
```

Линтер и форматтер:

```bash
ruff check .
ruff format .
```

## Структура

```
src/
  config.py     список городов (имя + координаты)
  fetch.py      Extract: запрос к Open-Meteo + разбор ответа
  storage.py    Load: SQLite — сохранение, чтение, агрегатная сводка
  report.py     Transform: расчёт изменений + сборка Markdown-отчёта
  main.py       оркестрация Extract → Load → Report
  paths.py      абсолютные пути проекта
tests/          тесты (pytest)
data/           база SQLite (в репозитории — хранит историю между запусками)
report.md       последний сгенерированный отчёт
```

## Как устроено

- Чистая логика (разбор ответа, расчёт изменений, сборка таблиц) написана по TDD и покрыта
  юнит-тестами; сетевые и файловые обёртки проверяются интеграционно.
- Агрегаты по истории считает СУБД (`GROUP BY`), а не Python — база делает это эффективнее.
- Пути к базе и отчёту передаются параметрами, поэтому пайплайн целиком тестируется на
  временных файлах, не затрагивая рабочие данные.
